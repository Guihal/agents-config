# Styling — Tailwind v4 и SCSS в SFC

Два инструмента одного вопроса «чем стилизуем SFC». v4-факты сверены с
официальными доками tailwindcss.com (2026-09-21). Организация стилей в целом
(слои токенов, специфичность, utility vs component) — не здесь, а в
`/home/penis/.agents/skills/css-architecture/SKILL.md`; ниже только Vue-слой.
Дефолты; проектные правила сильнее.

## Выбор: utilities или scoped SCSS

- **Tailwind-утилиты в разметке** — презентационный слой (= utility-слой
  css-architecture): значения по месту, состояния через `hover:`/`focus:`.
- **Scoped SCSS в SFC** — component-слой: состояния и модификаторы
  компонента, сложные/вложенные селекторы, стилизация вендор-компонентов,
  токены в переменных.
- Граница «не строить компонент из 15 utility, где нужен semantic-класс» уже
  сформулирована в css-architecture (закон 6) — ссылаться, не переизобретать.
  Tailwind-методология проекта сильнее — соседняя оговорка «когда отступать»
  наследуется как есть.

## Tailwind v4 — опорные факты

- **v4 — не с CSS-препроцессорами.** Официальная позиция доков: «not designed
  to be used with CSS preprocessors like Sass» — Tailwind v4 сам препроцессор.
  Tailwind-директивы в `lang="scss"`-блоках не поддерживаются; `@reference`/
  `@apply` там уходят в бандл литералами, стилей ноль (проверено на
  tailwindcss 4.x + sass). Директивы — только в plain `<style>`.
- **CSS-first:** конфигурация в CSS, не в JS. Вход — `@import "tailwindcss";`;
  `tailwind.config.js` не нужен (`@config` — только legacy-совместимость).
- **Токены — `@theme`:** CSS-переменные в пространствах имён (`--color-*`,
  `--text-*`, `--font-*`, `--spacing-*`, `--radius-*`, `--breakpoint-*`, …)
  создают утилиты (`--color-brand-500:` → `bg-brand-500`) и попадают в
  скомпилированный CSS как `:root`-переменные — по умолчанию только
  использованные, `@theme static` эмитит все.
- **Нативные cascade layers.** Кастомные утилиты — через `@utility`
  (работают с `hover:`/`sm:`/…), не через `@layer utilities` как в v3.
  Базовые переопределения элементов — `@layer base`; классы, которые утилиты
  должны уметь перебивать без `!important`, и стили сторонних компонентов —
  `@layer components`. Варианты в кастомном CSS — `@variant` /
  `@custom-variant`.
- **Сканирование исходников автоматическое** (кроме `.gitignore`,
  `node_modules`, бинарных, CSS, lock-файлов); недостающие источники —
  через `@source`.
- **Имена классов — только полные литералы.** Сканер читает исходники как
  текст и не понимает конкатенацию/интерполяцию: `bg-${color}-500` молча не
  попадёт в production. Решения: map с полными именами классов; условные
  `:class`-объекты (`:class="{'bg-blue-500 hover:bg-blue-600': variant === 'primary'}"`);
  действительно динамические значения — CSS-переменная через `:style`.
- Safelist — по необходимости и скупо: `@source inline("...")`. Привычка
  safelist из v3-конфига не переносится — механика другая.

### `@reference` в SFC — только в plain `<style>`

`@apply` и theme-переменные в `<style>`-блоке компонента требуют `@reference`
основного стилевого файла — без дублирования CSS в бандле. Блок — plain CSS,
не `lang="scss"`:

```vue
<style scoped>
  @reference "../../assets/main.css";
  .title {
    @apply text-2xl font-bold;
  }
</style>
```

С дефолтной темой достаточно `@reference "tailwindcss";`. В
`lang="scss"`-блоке `@reference`/`@apply` не работают — литералы в бандле,
стилей ноль; SCSS-блок — для SCSS-синтаксиса и `:deep()`/`:slotted()`.
Доки к тому же рекомендуют для Vue по возможности обходиться
utility-классами в разметке или CSS-переменными (`var(--color-*)`) без
`@apply`.

## SCSS в SFC — scoped-механика

- Scoped-компилятор вешает `data-v-xxx` на элементы своего шаблона и
  дописывает атрибут в селекторы. Элементы детей атрибут не получают → их
  стили молча не применяются.
- **`:deep()` — единственный синтаксис выхода к детям** (`>>>`, `/deep/`,
  `::v-deep` устарели; `>>>` не работает в SCSS). Ограничивать родительским
  классом: `.card :deep(.btn)` — голый `:deep(.btn)` бьёт по всему дереву.
  Корневой элемент ребёнка родительский scoped CSS затрагивает — намеренно,
  это layout-контракт.
- **Runtime-контент** (`v-html`, JS-манипуляции DOM, вендор-редакторы)
  `data-v-xxx` не получает. Лечение: `:deep()` для v-html; unscoped `<style>`
  с уникальным префикс-классом для вендорских инъекций; лучшее — не v-html,
  а реактивный шаблон (также по безопасности).
- **Слот-контент** компилируется в скоупе родителя: владелец слота стилизует
  его через `:slotted(x)` — только прямые slotted-элементы; глубже —
  `.wrapper :deep(x)`. Named slots — точечно: `.card-header :slotted(h2)`.
- **Класс-селекторы предпочтительнее element-селекторов** в scoped
  (`.title[data-v-x]` читается браузером легче, чем `p[data-v-x]`) —
  конвенция, согласованная с бюджетом специфичности css-architecture
  (закон 5).

## Слои токенов в Vue-стеке

- `@theme` — место primitive/semantic-токенов Tailwind-стека (цвета, шрифты,
  spacing, радиусы): источник значений утилит и `:root`-переменных.
- Scoped SCSS компонента — component-слой: компонент читает токены
  (переменные), не хардкодит литералы (законы слоёв — css-architecture,
  не пересказывать их здесь).
- `:deep()`/`:slotted()` — контролируемые выходы за границу изоляции; каждый
  такой селектор — расход бюджета специфичности (css-architecture, закон 5).

## Tailwind v3

Конфигурация в v3 — JS (`tailwind.config.js` + content), safelist в конфиге,
`@layer utilities` регистрировал утилиты — отличия систематические; в
v3-проекте сверяться с официальными доками v3, не смешивать конвенции.
