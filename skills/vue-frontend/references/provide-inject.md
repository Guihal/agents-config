# Provide/Inject — DI-контракты

Паттерны контрактов: кто владеет, как типизировать, где граница с props и
store. API-семантика — в официальных доках Vue (индекс: `vuejs.org/llms.txt`).
Дефолты; проектные правила сильнее.

## Граница: props / inject / store

| ситуация | инструмент |
| --- | --- |
| direct parent-child | props + emit |
| проброс глубже 1 уровня | provide/inject — координация внутри поддерева фичи (закон 3 SKILL.md) |
| несвязанные деревья, глобальное состояние | store (Pinia) |
| конфигурация плагина/приложения | `app.provide` того же typed key |

provide/inject против store: поддерево против глобального; DevTools-поддержка
у store полнее — долгоживущее общее состояние ведёт store.

## Контракт ключа

```ts
// injection-keys/auth.ts
import type { InjectionKey } from 'vue'

export interface AuthContext { /* ... */ }

export const AuthKey: InjectionKey<AuthContext> = Symbol('auth')
```

- **Symbol + `InjectionKey<T>` — дефолт.** String-ключи сталкиваются в
  больших приложениях и библиотеках (выигрывает ближайший предок — конфликт
  незаметен); symbol уникален. Тип ключа даёт проверку `provide` на этапе
  компиляции и тип `T | undefined` у `inject`.
- Исключение, где string допустим: маленькое приложение, локальное поддерево,
  прототип; неймспейс `'myapp:config'` снижает риск.
- Организация — по доменам: `injection-keys/auth.ts`, `theme.ts`, `index.ts`
  с реэкспортом. Ключ — отдельный файл, не инлайн в компоненте.
- Generic-ключи для коллекций:
  `createListKey<T>(name): InjectionKey<ListContext<T>>`.
- Владелец контракта — провайдер (верх поддерева, обычно L1 Feature); ключ
  и типы контракта живут рядом с ним.

## Дефолты и undefined

`inject(key)` возвращает `T | undefined`. Стратегии:

- Инъекция опциональна → **дефолт-значение**: убирает undefined.
- Значение создаётся на потребителя → **фабрика**:
  `inject(key, () => ({ ... }), true)` — третий аргумент заставляет вызвать
  фабрику, ссылки не шарятся между потребителями.
- Контракт обязателен → **guard с содержательным throw** (или обёртка ниже).
- `inject(key, undefined)!` — по минимуму: глушит контракт, а не выражает его.

## Обёртка-композабл (обязательный контракт)

```ts
export function useAuth(): AuthContext {
  const ctx = inject(AuthKey)
  if (!ctx) throw new Error('useAuth: нет провайдера — wrap in <AuthProvider>')
  return ctx
}
```

Потребители не знают про ключ; контракт проверяется в рантайме с подсказкой,
что сделать.

## Мутации — у провайдера

- Наружу — `readonly()`-данные + явные функции обновления: валидация и
  сайд-эффекты централизованы, DevTools показывает, откуда пришло изменение.
- Прямая мутация предоставленного состояния из injector'а — антипаттерн:
  «кто изменил?» не прослеживается.
- Когда отступать: локальное состояние маленького поддерева, изолированный
  wizard — и там лучше readonly + функции.
